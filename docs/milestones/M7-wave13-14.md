## Wave 14 — New Features

Wave 14 adds six areas of new functionality built in parallel by dedicated builder agents.

### Builder A — Payment Stubs + QR Check-in

**Owned paths**: `packages/contracts/src/payments.ts`, `modules/payments/**`,
`mobile-features/account/src/payments/**`

**Features delivered**:

1. **Payment contracts** (`packages/contracts/src/payments.ts`)
   - `Wallet` schema: `balanceIqd`, `heldIqd`, `availableIqd` (all integer IQD, no fractions)
   - `PaymentMethod` discriminated union: `card | wallet | cash_on_delivery`
   - `PaymentIntent` with full status lifecycle and `flaggedForReview` field
   - `paymentsContract`: wallet (get/transactions/top-up), methods (CRUD), intents (create/get/confirm/cancel/refund/list)

2. **QR check-in flow** (mobile-features/account)
   - Camera screen using `expo-camera` to scan QR codes placed at venues
   - QR payload: signed JWT containing `placeId` + venue public key
   - On successful scan: calls `POST /v1/checkins` with `method: "qr"`
   - Anti-replay: QR tokens include `iat` and are valid for 24h only

**Line counts**:
- `packages/contracts/src/payments.ts`: ~300 lines
- `modules/payments/`: ~800 lines (service + controller + migrations)
- `mobile-features/account/src/payments/`: ~400 lines
- `mobile-features/account/src/qr/`: ~250 lines

### Builder C — Crowding Heatmap

**Owned paths**: `modules/insights/**`, `mobile-features/map/src/heatmap/**`

**Features delivered**:

1. **Crowding heatmap layer** on the map
   - Aggregates crowding reports per H3 cell (resolution 9, ~0.1 km²)
   - Colour ramp: green (quiet) → yellow (moderate) → red (busy)
   - Updates every 5 minutes via BullMQ job (`insights.crowding.refresh.v1`)
   - Cached in Redis with 5-minute TTL; served as GeoJSON from the API

2. **Crowding report submission** (crowd-source)
   - Users can submit "busy / moderate / quiet" reports from the place card
   - Reports older than 2 hours are excluded from the heatmap
   - Requires authentication; limited to 10 reports per hour

3. **Peak hours chart** in provider insights
   - Aggregates check-in timestamps into hourly buckets per place
   - Displayed as a bar chart in the provider dashboard

**Line counts**:
- `modules/insights/`: ~600 lines
- `mobile-features/map/src/heatmap/`: ~300 lines
- `packages/contracts/src/insights.ts`: ~150 lines

### Builder E — Appointments System

**Owned paths**: `packages/contracts/src/providers.ts` (appointments section),
`modules/providers/src/appointments/**`, `mobile-features/provider/src/appointments/**`

**Features delivered**:

1. **Appointment booking** (mobile)
   - Date/time picker on the place card (for providers with `verified` status)
   - Form: date, time, service description, optional notes
   - Confirmation screen with appointment summary
   - Push notification on status change (`confirmed`, `cancelled`)

2. **Provider appointment inbox** (mobile)
   - List view of pending/confirmed/completed appointments
   - Swipe-to-confirm and swipe-to-cancel actions
   - Sort by date ascending (soonest first)

3. **Backend appointment service**
   - `modules/providers/src/appointments/`: NestJS service + controller
   - State machine: `pending → confirmed | cancelled → completed`
   - Status change events published to outbox (`providers.appointment.status_changed.v1`)

### Builder G — Backend Performance + Monitoring

**Owned paths**: `apps/api/src/**`, `packages/observability/**`

**Features delivered**:

1. **OpenTelemetry tracing** (opt-in, env var gated)
   - `OTEL_EXPORTER_OTLP_ENDPOINT` enables OTLP export
   - Spans on every NestJS controller method and Drizzle query
   - Trace context propagated to BullMQ workers via outbox headers

2. **Health check endpoint** (`GET /healthz`)
   - Checks: PostgreSQL connectivity, Redis ping, Valhalla reachability, Photon reachability
   - Returns `200 { ok: true, checks: {...} }` or `503` with failing services listed

3. **DB query performance**
   - Added missing composite indexes on `places.city_id + location` (PostGIS spatial)
   - Added `providers.status + created_at` index for admin queue
   - Slow-query logging: queries > 500 ms log at WARN level with the query plan

4. **Rate limit improvements**
   - Redis Sliding Window rate limiter replacing the previous fixed-window implementation
   - Per-endpoint overrides now configurable via env vars without a code deploy

**Line counts**:
- `packages/observability/`: ~400 lines added
- `apps/api/src/`: ~300 lines (health controller, middleware changes)
- Migrations (index additions): ~80 lines

**Owned paths**: `geo-services/**`

**Features delivered**:

     `natural` feature classes in the Baghdad PMTiles file

2. **Photon geocoder improvements**
